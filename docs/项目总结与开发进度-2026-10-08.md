## 一、这个项目想实现什么

### 1.1 一句话定位

**给 Avalonia 12 做一套"可被验证的" Material Design 3 / M3 Expressive 控件库，附带一个模仿 m3.material.io 官网信息架构的组件 Gallery —— 而不只是给 Avalonia 换一层 Material 皮肤。**

项目自己把"精准模仿"定义为可验收项（设计规范 §3）：颜色取 sRGB 令牌值、几何误差 ≤ ±1 DIP、字体/状态/动画/图标/交互/Gallery 信息架构逐项对齐，并把"规范冻结"（记录来源 URL、抓取日期、AndroidX commit SHA）作为实现前提。

### 1.2 五条硬约束（决定了它和普通控件库的区别）

| 约束 | 含义 |
|---|---|
| 独立 `Md*` CLR 类型 + scoped `ControlTheme` | **禁止** `Style Selector="Button"` 这类全局覆盖；允许继承原生控件复用行为和 AutomationPeer |
| 核心包不依赖 `Fluent` / `Simple` 主题 | `Md3.Avalonia` 自带完整 token 与模板，可独立渲染 |
| 核心不引用桌面专属 API | 与 Android 同级优先（Tier 1），当前以 `net10.0` / `net10.0-android` 为 CI 基线 |
| 颜色/字体/形状/间距/阴影/状态/motion 全部走 token | 返回 `DynamicResource`，运行时换主题不重建模板；禁止模板里散落硬编码 |
| MVVM 与直接操作双入口 | 全部 bindable API 都是 Avalonia property，同时保留 `Command`/事件/直接方法（`Show()`/`Dismiss()`/`ShowAsync()`） |

### 1.3 交付形态

- **6 个可独立发布的 NuGet 包**：`Md3.Avalonia`（核心）、`Md3.Avalonia.Icons`、`Md3.Avalonia.Icons.Lite`（可选图标 provider，内嵌官方 Material Symbols Rounded 字体）、`Md3.Avalonia.Extra`（Flutter clean-room 扩展控件）、`Md3.Avalonia.DataGrid`（Avalonia 原生 `DataGrid` 的 Material 主题）、`Md3.Avalonia.RichEditor`（AvaloniaRichEditor 的 Material 主题）。后两者是 opt-in，不用就不会被依赖拖进来。
- **Gallery**：桌面（三栏文档 shell）+ Android single-view 宿主；94 条导航条目 / 98 个页面文件、每页含 AXAML/C# 双语言可复制示例、Theme Lab（任意 seed 色 / 6 种 scheme / 3 档对比度 / JSON 导入导出）。
- **验证基础设施**：`spec-snapshot/`（外部 oracle）+ `scripts/`（字体校验、token lint、API 文档覆盖、oracle 同步）+ `tests/`（headless 行为/几何/渲染/规范分层测试）。

### 3.2 工程与质量基础设施（项目最突出的部分）

- **规范 oracle**：`spec-snapshot/manifest.json` 固定了 m3.material.io 各页面 URL + 抓取日期、冻结的 `androidx/androidx` commit `e2171b56…`、Flutter 版本、字体 commit、Avalonia 版本，以及明确的 `claim_policy`（项目"拒绝声明"的清单）。`tokens.json` 带 confidence（`high` 可阻断构建，`medium` 只报告）。**规定该文件永远不能由本仓库生成**，只能由 `sync-spec-tokens.py` 从上游重新抓取比对。
- **分层验证 L0–L5**（`docs/SPEC_VERIFICATION.md`）：L0 静态 lint（无 SDK，<1s）→ L1 token 经真实资源系统合并后的取值 → L2 排列几何与 48×48 命中 → L3 视觉金图（首跑不自动采纳自己的输出）→ L5 弹簧物理（对照 RK4 积分、收敛阶、settling 点）。
- **棘轮机制**：`conformance-policy.json` 的 `mode` 已从 `bootstrap` 切到 **`enforce`**，当前记录为 **0 个 high-confidence gap**（L1 172/178 通过、L2 119/120、L5 51/51 + 18/20），剩余项全部有理由、且不会让构建失败。文档里还完整记录了"导航栏/导航轨两次把 oracle 改错、后来证明库是对的"的教训。
- **构建/CI**：`CI`（静态检查 + build + headless 测试 + 规范报告）、`Build NuGet Packages`（含内嵌字体校验与包资产校验）、`Build Multi-Platform Gallery`（Linux/Windows/macOS + Android APK）、`AOT probe`（调用 `scripts/publish-gallery-aot.sh`：发布原生 ELF、断言无托管 dll、IL 诊断为零、在 xvfb 下真实启动）、`Sync Wiki`、Android Maestro。**main 上最近一次全部为 success**。
- **可实测的合规细节**：我核对仓库内嵌的 `MaterialSymbolsRounded.ttf`，SHA-256 = `95b24392bb49efd1bc3e92cff4e2452ad094461bab7c97e7d8723fab97e330ca`，与 README/校验脚本声明的哈希一致；`python3 scripts/lint-design-tokens.py` 本地复跑结果为 `mode=enforce errors=0 warnings=371`。
- **依赖与裁剪**：全部包声明 `IsTrimmable` + `IsAotCompatible` 并开启 IL2xxx/IL3xxx 分析器；主题 JSON 走源生成序列化；字符串属性路径都提供免反射委托。

## 四、总体判断

1. **目标已经基本实现的是"覆盖面 + 工程可信度"**：官网组件目录 100% 有对应实现，超出目录的 Flutter/生态控件也已成体系；更难得的是它建立了一套"外部 oracle + 分层验证 + 棘轮门禁"的机制，并主动撤回自己曾经的"100% 合规"声明。这种自我否证（audit → 撤回 → 整改 → 再把棘轮从 bootstrap 推到 enforce）在个人控件库里很少见。
2. **当前处在 0.4.x preview 的"功能完成、验收未完成"阶段**：代码侧 P0 已关闭（我抽查了 `MdModalFocusController`、`MdRangeSliderAutomationPeer`（双 thumb `IRangeValueProvider`）、`MdTimeDialAutomationPeer`、`MdCalendarGridAutomationPeer` 等，确认审计中的 P0 已有对应实现），但**平台真机、屏幕阅读器、Gallery 规格偏差、部分文档一致性**这四块是明确的未完成项，项目也坚持不把它们写成"已完成"。
3. **近期工作重点**（从时间线看）：不再是"加控件"，而是 **打包/裁剪/AOT、跨框架版本、Gallery 细节与可达性、文档与代码对齐** —— 这是从"组件库"走向"可发布 1.0"的典型收尾姿态。
4. **可用性结论**：作为预览版/内部应用/组件参考，现在就可以用（`net10.0`，Android 宿主可编译）；作为宣称"符合 Material Design 3 规范"的正式发布，还差平台验收与 Gallery 偏差收敛两步。
